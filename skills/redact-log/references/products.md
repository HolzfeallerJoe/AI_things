# Bat-X product coverage

Reviewed on 2026-10-08 under the user's Bat-X project directory. Product repositories were read only. Actual user/customer values and raw log samples are deliberately absent from this reference.

The original validation covered 34 existing text log files, including installed desktop logs, twelve FoodRecall client exports, the repository-local scraper log and nine SendMe development/build logs. All retained record-line counts and the checked symbolic error codes, produced idempotent redaction, and left source hashes unchanged. A real client export also passed the separate-copy CLI and residual scan with a shifted timeline. The diagnostic-preservation revision of 2026-10-13 is validated separately using synthetic cases for updater versions, complete URL parameter structure, hostless media queries, source ID policy, original timestamps and optional jointly shifted expiry times. Historical runtime validation is not a rerun of the revised helper. Tests verify transformation behavior, not exhaustive identification of private prose.

## Log discovery

Desktop X-Core products commonly write `%LOCALAPPDATA%/Abelssoft/<product>/app.log`. Companion logs include SendMe `main_process.log` and YouTube Song Downloader `net.log`. The reviewed EverDoc desktop installation also has `logfile.log`, `EverDocTwain32.log` and `Index/log.txt`; its mobile repository is separate.

Capacitor/Ionic apps commonly retain logs in the app's logging/localStorage layer and expose a support export. These are not automatically standalone Windows files. Only read the actual exported logs or app-specific log output that the user authorizes. Android logcat must be filtered to the relevant app process. Do not launch apps, capture unrelated apps, or read databases/preferences containing private application data merely to find logs.

FoodRecall API supports a local `logs/requests.jsonl` path through `REQUEST_LOG_FILE_PATH`. ABC-Todo and Voice2Mail APIs use Pino/stdout, so a running local process/container or an existing console export is needed. The Java media scraper has `app/tmp/log.txt`. Docker was not running during this review; no live API-container logs were available. The connected Android phone had these mobile apps installed but none running; no fresh app-specific logcat output was available. Do not claim runtime-log validation for those apps.

Exclude binary Chromium/LevelDB `000003.log` files from the text-log helper. A `.log` suffix alone does not make a file a textual application log.

## Desktop and shared infrastructure

- **YouTube Song Downloader, Doku Downloader, Mediatheken Downloader, X-Loader:** use `media` plus `x-core`. Actual installed `app.log` files were reviewed, together with YSD `net.log`. Findings include profile paths, download/library roots, personal file/album selections, searches, media URLs, public IPs, credentials and tracking identifiers in URL parameters. Preserve format IDs, conversion steps, media lengths, duplicate/queue flags, file extensions and move/stat errors. Preserve YouTube source video IDs and matching metadata IDs by default, with `--redact-media-ids` for confidential selections. Keep technical event/expiry timestamps, updater channel/build strings, HTTP context and downloader options. Compare complete and hostless signed media queries parameter by parameter so retries and renewal remain distinguishable without exposing signatures. Source references include YSD `src/app/pages/search/search.component.ts`, `src/app/pages/album-detail/album-detail.component.ts`, and the corresponding downloader logging scopes. Clipboard prose and full media-object dumps need review as well as `title=` fields.
- **KeyDepot:** use `keydepot` plus `x-core`. Actual `app.log` reviewed; it contained email/account references, vault paths/names and credential-labeled fields. Cloud-service prose contains usernames and backup-safe names. Mask account identities, safe names, personal database/keyfile locations, credentials, entry titles/URLs/notes and any decrypted entry payload. Preserve database format/version, backup/copy/import steps and crypto/error outcomes. Sources: `src/app/services/CloudService.ts`, `IoService.ts`, `AppdataHelperService.ts`. Do not open vault databases or keyfiles for redaction research.
- **SendMe / send2phone desktop and QRSend desktop:** use `sendme` plus `x-core`. Actual installed `app.log`, `main_process.log` and local desktop build/dev logs reviewed. Findings include local network IPs, MACs, peer/device names and identifiers, filenames, message/share data and tokens. Preserve host equality, ports, connection direction, discovery/reconnect and transfer counts. Sources: `SendMe/send2phone-desktop/src/app/services/network.service.ts`, `SendMe/qrsend/electron/server.ts`, `eventlog.ts`. QR paths `/box/<pairToken>`, `/f/<token>`, `/u/<token>` and `/z/<token>` carry access material; mask the token while retaining the route shape.
- **BetterRhythm:** use `better-rhythm` plus `x-core`. Installed `app.log` reviewed; the inspected file had technical logger output without obvious personal payloads. Source `src/main/debug-event-log.ts` explicitly exports a reduced activity/lifecycle event view. If an expanded diagnostic export contains window titles, foreground content, paths or activity history, redact those; preserve activity transitions and intervals. Do not assume those private fields appeared in the inspected file.
- **PcChangeMonitor:** use `pcchangemonitor` plus `x-core` when applicable. No standalone runtime log found in the inspected product locations. Source-only evidence: `app/snapshot.service.ts` logs scan failures, commands and payloads; UI snapshot diagnostics can contain paths and program metadata. Review registered owners, organization, machine GUID/SID, custom services/tasks, personal command-line arguments and registry values. Keep scan step, installed-public-software identity, OS/build, counts, duration and error category.
- **X-Core:** shared infrastructure, not a separate consumer-product log. Review registration/license/account/device fields in every host product. Sources: `projects/asc/x-core/src/lib/logging/log-providers/file-log-provider.service.ts`, legacy logger service, registration/license/telemetry services. Product IDs, promo tags, app version, company/public product names, registration booleans and event counts are usually technical constants; customer-specific IDs and dates are not.

## Mobile products and their APIs

- **FoodRecall / RückrufRadar client and backend:** use `foodrecall`. Twelve existing client exports under Downloads were reviewed. Observed fields include session/request identifiers, API URLs, private host IPs, search/subscription context and stream diagnostics. Backend runtime logs were unavailable; source `foodrecall-backend/src/app/request-logs.ts` adds `user_trace_id`, `client_session_id`, request IDs, user-agent and query context. Hide tracking IDs, push/APNS/FCM/subscription access data, personal search/filter preferences and precise user location. Preserve public recall/article/product/source identifiers and facts, request method/status, polling/database operations, counts, event/source/state and stream/reconnect behavior. A public recall's place/title is not automatically the customer's location/name.
- **ABC-Todo app and backend:** use `abc-todo`. Source-only coverage; no standalone runtime export found. App `src/app/services/log.service.ts` already masks some titles, URLs and paths and exports `logs/abc-todo-client.log`. Backend `backend/logger.ts` uses Pino redaction and strips request query values in its request serializer. Still review session/device IDs, device and pairing tokens/codes, task titles/notes/descriptions, board IDs and database URLs. Preserve sync/conflict state, counts, route, retryability, request relations and timestamps as intervals. Existing app-level redaction is not proof that all user content has been removed.
- **SendMe mobile, legacy Capacitor and QRSend React Native:** use `sendme`. Source and local Android build/Metro logs reviewed; no live runtime capture was available. Legacy logs live in an Ionic logging layer. New `qrsend-mobile/src/eventlog.ts` is a bounded in-memory buffer included in diagnostics. Review peer aliases, contacts, chat/clipboard payloads, private filenames, share/PIN/pair tokens, Wi-Fi/IP/MAC and notification data. A connectivity report intentionally excluding pair tokens may still contain host/device identity.
- **EverDoc mobile:** use `everdoc`. Source-only mobile coverage; the actual desktop companion logs were reviewed. `src/app/pages/about/about.page.ts` prepares a logging export; `qr-scan/qr-scan.page.ts` logs scan results and `services/everdoc-desktop.service.ts` can log failed request objects. Review QR pairing/access codes, desktop user IDs, personal document/file names, OCR/text/tags, scanned images and upload paths. Preserve upload status, file type/size, request outcome and scanner/connection errors.
- **ScamCheck mobile:** use `scamcheck`. Source-only coverage; no runtime export found. The existing `src/app/utils/log-sanitizer.ts` already hides receipts/tokens but retains truncated transaction IDs and limits strings. Replace retained purchase-ID tails too. Review login/email, license/auth fields, analyzed/shared text/URLs/screenshots, tokens, receipts, signatures and personal content inside plugin/HTTP errors. Preserve entitlement state, public SKU, platform, status, error name/code and receipt/token length, not the actual receipt/token.
- **Voice2Mail app and API:** use `voice2mail`. Source-only runtime coverage. App `src/app/services/send-queue.service.ts` logs `voiceList`, upload queue and filenames/recipients; `email-list.service.ts` logs address lists. API `src/validation.ts` accepts recipients and location; `src/app.ts` deliberately emits reduced request records and `src/server.ts` uses Pino. Review recipients, recording names/paths, spoken/text content, mail subject/body, GPS/place names, installation/key/principal identifiers, integrity/attestation/assertion values and SMTP/authentication fields. Preserve queue order, file type/length, language, conversion/SMTP outcome, route, HTTP status and elapsed duration.
- **Triply:** use `triply`. Source-only coverage; no runtime export found. Sources: `src/app/services/trip-storage.service.ts`, trip-edit/details views and notification payloads. Review display name, destinations, travel dates, trip notes/checklists/documents, personal filenames and reservation/identity information if included in a diagnostic dump. Preserve operation, entity relationships, checklist counts, notification action and errors.
- **Timeflow / timeRevision:** use `timeflow`. Source-only coverage; no standalone runtime export found. `src/app/home/date-picker/date-picker.component.ts` logs vacation requests, arrays and selected start dates. Review employee identity, leave reason/category and exact absence periods. Preserve request status, date ordering/interval where needed, item counts, validation errors and API outcome. Arbitrary console arrays with no field label require contextual review.
- **Media DL API / Mediathek Java scraper:** use `media`. Actual repository-local `app/tmp/log.txt` reviewed. The source `app/src/main/java/Controller/DoogiesRequestLogger.java` logs request URI/payload/duration. Review URI query values, custom hosts, environment paths and any personal request/response data while preserving public provider/content-schema metadata, parsing exceptions and request results. A crawler's public catalogue is not automatically user search history; use the record's context before treating every public title as a private selection.

## Browser extension and nonproducts

- **TabTimeKeeper:** use `tabtimekeeper`. Source-only coverage; no exported runtime log found. `shared/tab-model.ts` holds URL/title/favicon data. Review page URLs, queries/fragments, tab titles and browsing timing in diagnostics; retain tab relationships, age/duration, state and extension errors. Public browser/extension versions and exception source lines are diagnostic.
- The top-level `artifacts` folder contains outputs rather than a separate product. Build dependencies, caches, vendored libraries and design exports are not extra products or user-runtime log sources.

These profiles record supported rules and review targets, not a claim that every possible sensitive value was observed in a live log. Maintain new rules using synthetic fixtures, and distinguish runtime evidence from source-only inference in reports.
